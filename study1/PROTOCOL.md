# Tanker allocation study protocol

Version 1.2, specified before any model data collection. Version 1.2 (8 October 2026) moves the same model pair from 8-bit and 4-bit Mac builds to the published bf16 checkpoints on the Deakin cluster; nothing else in the design changes. Version 1.0 named a paid Anthropic model pair; version 1.1 replaces it with two open-weight models served locally, and changes the design only where that requires it: cost is no longer measured, and failed local requests may be retried. The change is recorded in `../DEVIATIONS.md`. This is an exploratory computational study of the allocation method. The earlier thesis supplies the task sequence and training purpose, not these generated positions, transmissions, channels or answer keys. No exercise records, commercial-in-confidence material or human participant responses are used. The original manuscript and run brief are preserved; changes are itemised in `../DEVIATIONS.md`.

## Materials

Generate 64 test instances and 32 separate held-out instances using seed 20261007, with split-specific seeds 20261008 and 20261009. Freeze the JSON, configuration, source and protocol hashes before calibration. The test set has 32 direct calls, 16 calls with a resolvable addressee ambiguity (aircraft two or three, of which only aircraft two is controlled), and 16 calls to uncontrolled aircraft three. Each address group crosses clear, busy, unexpectedly jammed, and scheduled-jamming states in a balanced 16-cell design. The held-out set has the same proportions. These are designed strata, not estimates of frequencies in real exercises.

Four phrasings order a tanker join and a report at 10, 15, 20, 25 or 30 NM. Aircraft two starts with x and y independently uniform from −5 to 5 NM, heading 90 degrees and speed uniform from 420 to 480 knots. The tanker has centre x uniform from 50 to 80 NM, centre y from 35 to 60 NM, circular radius from 6 to 10 NM, speed from 260 to 300 knots, and initial phase from 0 to 2π. Tanker callsign is SHELL 1 or SHELL 2; primary channel is 5 or 6 and backup is 7 or 9. Trainee level is initial employment or LFE proficient. The deviation inject and public plan intent are independently sampled. The private scripted plan selects misinterpretation only for an LFE proficient trainee with a deviation inject; otherwise it selects compliance. A recover-communications plan defers during scheduled jamming; a basic-join plan uses backup. The deviation choice is recorded but not enacted as a different flight trajectory: this study does not evaluate trainee learning or intentional pilot errors.

An unacknowledged instruction stops the plan after ACK and produces a FLY status report without moving or calling. The reporting distance, full orbit parameters and current aircraft state are explicitly declared where needed. Every condition receives adequate observations for the decision being tested. Neither the private scripted answers nor the generator's answer key is sent to a model or router.

## Conditions

Run five independent requests per instance and condition. Randomise the condition/instance/repetition schedule with seed 20261009. Independent runs may execute in parallel (`run.py --workers N`, frozen in the manifest); the five policy orders run in parallel, each sequential within itself. Time per run is then measured under shared load and is reported with the worker count. Each repetition starts with a new policy store; persistence is tested separately.

1. **Single:** one strong-model request receives the whole scenario, public training intent, physics and task specifications, and returns payloads keyed by task ID. It chooses DEV and a scheduled-jamming response itself. Private human choices are not revealed.
2. **Decomposed:** the strong model makes all eight machine decisions in sequence. A forced-candidate prompt disables abstention; a malformed payload fails the run and scores the remaining required decisions incorrect. There is no human rescue of machine decisions. DEV uses the scripted plan.
3. **Routed:** deterministic tools make their original six decisions. A frozen RouteLLM BERT checkpoint chooses small or strong for ACK and CALL, using the median held-out routing score to target 50% strong calls. Ties use strong and the realised fraction is reported. Forced candidates disable abstention; malformed candidates fail the run. DEV uses the scripted plan. The classifier runs locally in evaluation mode; router runtime is included and its provider-token cost is zero. This off-the-shelf preference classifier was trained for a different model pair, so transfer is a limitation, not evidence of an optimal router.
4. **Allocated:** the ordered allocation clauses, schema and budget checks, calibrated confidence gates, abstention, escalation and scripted human recovery operate together. Six decisions use tools, ACK and CALL start at the small model, and DEV is human-authorised. Policies store exact decisions only within their declared observations, orientation/intent and task-design version. CALL also keys both ordered and observed distance; variable reports cannot be reused as generic radio policies.

The model configuration is in `config.cluster.json`. Both tiers run on one node of Deakin University's A2I2 cluster, launched by `cluster/study1.sbatch` and `cluster/serve.sh`, as open-weight models served by vLLM 0.30.0 (CUDA 12.9 build). The small model (T1) is `Qwen/Qwen3-4B-Instruct-2507` at revision `cdbee75f17c01a7cc42f958dc650907174af0554`, on one NVIDIA L40S. The reasoning model (T2) is `Qwen/Qwen3.8-27B` at revision `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`, tensor-parallel on two L40S GPUs, with thinking enabled and the server's reasoning parser separating its reasoning from the answer. Both run in their published bf16 form. The GPUs are those SLURM allocates to the job, split in the order SLURM lists them. Sampling uses each model's published generation defaults, stated explicitly in the configuration. Output is limited to 4,096 tokens for T1 and 16,384 for T2, including reasoning. T2 runs with the chat template's `reasoning_effort` set to "medium"; the template default, "xhigh", made held-out reasoning overrun 8,192 tokens. No `thinking_token_budget` is set, so the output limit is the only hard cap. Both servers use a 32,768-token context. Use the same pair in every condition. At the start of a run the backend records each server's listener, launch arguments, model snapshot hashes, CUDA dependencies, GPU assignment and SLURM job, and it stops if any of these changes; start a new output directory instead of mixing records. Log request and raw response, token usage as counted by the server, response ID, UTC time and latency. Cost is zero and is not a study measure; time per run is measured on the stated hardware. Save a request journal before sending. A local request that fails without a response is not billed, so it may be sent again on resume; the failed attempt stays in the journal and the analysis checks that every request ends in exactly one response. Do not reuse responses across scientific repetitions. Resume may replay only the same uniquely identified request.

Version 1.1 first ran the same two models as 8-bit and 4-bit MLX conversions on an Apple M4 Pro (`config.open-weight.json`). That configuration was used only for held-out verification and is kept as a record; it is not used for collection.

The Anthropic configuration of version 1.0 remains in `config.example.json` and the paid backend remains in the code, with its spending cap and billing safeguards, for a later replication. It is not part of this study.

## Scoring and diagnostic calibration

Score named fields mechanically, without a model judge. ACK requires the correct addressee, join instruction, ordered distance within 0.01 NM, and acknowledgement flag. LOC requires the correct tanker and exactly one radius (a number in NM) and one speed (a number in kts or knots), each within 0.01 of the briefing values, however the orbit is otherwise worded; SEL the correct aircraft; CFG readiness and a line from aircraft 2 to the correct tanker, named in full. Allowed enum values are part of the hand-off specification, so diagnostics, calibration and analysis reject the same invalid values as the runtime. A reply is read as the first complete JSON object with a `decided` field, or, failing that, the first complete object. HDG must be within 1 degree of an independently bracketed-bisection intercept reference, with intercept time within 0.2 minutes. WAIT must report the first five-second crossing, with distance within 1.25 NM and elapsed time within one minute. The distance allowance covers five-second sampling at the largest combined speeds in the generator and rounding. CALL requires correct status and channel, and a made call must contain the control callsign, own callsign, tanker and exactly one distance matching the order within 0.01 NM. Every model input states what this scoring requires: CALL receives the control callsign in its comms plan, the allowed status values, the busy and jammed channel procedure and the report format, and every enum hand-off field lists its allowed values. A deferred message must explicitly hold, wait, retry or defer. FLY checks goal status and distance, with the 1.25 NM tolerance. Additional movement or calls after a misaddressed instruction invalidate FLY.

Primary accuracy is the mean proportion of required epistemic task payloads correct in each instance, then averaged across instances and repetitions. Misaddressed cases require ACK and FLY. Scheduled-jamming CALL and FLY are excluded from epistemic scoring because the response depends on a normative training choice. DEV is always excluded. Report per-task scores and failures alongside the aggregate, because eligibility differs between strata. This is end-to-end accuracy against a reference path; upstream errors can affect several downstream decisions. Scripted human recovery can improve final accuracy in the allocated condition and must be reported with requests to people; it is not model accuracy.

On held-out instances only, make five candidate-plus-abstention diagnostic requests to each model for each eligible ACK and CALL context. The context is taken from a clean reference trajectory, irrespective of the allocation. The same response must contain both its best candidate and its decision/abstention flag. Invalid candidates count as incorrect and abstained. Choose the lowest confidence threshold giving at least ten accepted diagnostic responses and at most 5% observed candidate error. This empirical calibration target is not a statistical guarantee on test cases. If no gate meets it, disable autonomous acceptance at that task/tier (represented internally by a gate above the possible confidence range). Freeze the gates and router threshold before test calls. Repetitions are clustered by instance in analysis.

For RQ2, repeat those paired diagnostics on eligible test ACK and CALL contexts. Report abstention among incorrect candidates and among correct candidates, separately by tier, with denominators. This tests two clause-F tasks. It does not test clause G or every task in the hierarchy. A forced candidate may affect willingness to abstain; this is a diagnostic measurement limitation.

## Policies and analysis

Run the 64 test instances in five orders with seeds 20261101–20261105, each beginning with an empty policy store retained only within that order. Count judgement requests, notices, approvals, policy applications and final-report size separately. Simulated people authorise DEV and scheduled-jamming choices and supply reference recovery after machine rejection. Their error-free answers are a simplifying assumption. CALL's exact continuous-distance keys may rarely recur; any decline in requests is expected primarily from recurring DEV situations.

Average repetitions within instances. For condition means and paired differences, use 10,000 percentile bootstrap resamples of instances, seed 20261010, with the same draws for all conditions. For diagnostic rates, resample instance-level numerator and denominator counts jointly. Report undefined rates as unavailable when their denominator is zero. Compute per-tier tokens as counted by the model server, total input/output tokens, maximum input context, run time, and completion counts. Include reasoning tokens in output usage. The analysis still writes a cost column; with local models it is zero and is not reported. Text shown to people is a character-based size estimate, not model-counted tokens, measured reading or workload; the final hand-off is reported separately from judgement requests, notices and approvals.

### Failed attempts and completion time (Simon approved, 7 October 2026)

Measure the active execution interval under shared load, including router execution and waiting during that interval. On resume, add the saved durations of successful calls replayed from the journal and measured failed attempts from earlier invocations. Count each duration once: failures during the current active interval are already included. Do not add offline gaps or infer missing durations from wall-clock timestamps. The backend records server and serving-evidence checks once at construction, outside the run's timed execution. This is run completion time under the stated collection setup, not isolated inference latency or a reconstruction of all process overhead before an interruption.

If any failed attempt for a run has unknown duration, save its `time_s` as null. Keep that run's accuracy, required-task scores and observed-response token totals. Report failed-attempt and retry counts separately in `retry-summary.csv`; `results.json` also totals attempts across the complete provider ledger, including calibration and diagnostics. Token totals cover server-returned usage from observed responses. An interrupted attempt without a saved response can have unobserved token use; neither impute it nor claim complete server-computation totals.

For timing means, average available repetitions within each instance, then average the instances with at least one timed repetition. For paired timing differences, use repetitions with an available time in both conditions, average their differences within each instance, then average the available instances. Use the same 10,000 seeded instance draws as the other measures, averaging available instance values in each draw. A draw with no timed instance has unavailable timing; report the number of usable draws. Report available and unavailable runs and instances and the timed-repetition counts by instance. If no timing is available, report an unavailable mean and interval. Accuracy and observed-token analyses continue to include all repetitions. Timing estimates describe the available subset and may be affected by missingness and shared load.

For policy sequences report each order, the means over its first and last ten instances, the mean change and range across orders. Do not apply an independent-instance bootstrap to stateful policy sequences, or treat the five orders as five independent experimental samples. These orders are sensitivity checks using the same cases. There are no hypothesis tests or outcome-dependent exclusions. Preserve failed model outputs in the denominator and original logs. A final analysis requires complete condition, diagnostic and policy records and provider evidence. Mock runs must remain labelled and are rejected by the research-analysis gate.
