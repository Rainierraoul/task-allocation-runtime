## Approved decision: failed attempts and the timing measure

Proposed by Codex and approved directly by Simon on 7 October 2026, before frozen collection. The harness, missing-time-aware analysis, tests, protocol and manuscript build script now implement this definition.

The local backend now preserves each attempt separately, records measured duration for caught failures and marks duration unavailable after a hard process interruption. A response durably saved before interruption is recovered without another inference. Failed-attempt timing summaries retain the known subtotal and report the total as unavailable if any attempt's duration is unknown. These are recording repairs, not a scientific decision about timing.

Include measured failed-attempt duration once in the affected run's reported completion time; exclude the offline interval between stopped and resumed processes; report failure/retry counts separately. If a hard interruption leaves an unmeasured attempt, retain that run in accuracy and token analyses, mark its completion time unavailable, and report the timing denominator for each condition. Do not discard the run or rerun a completed response to obtain a preferred timing result. The current active interval already contains current failures; only prior measured failures and replayed successful call durations are added.

Timing aggregation averages available repetitions within instances and available instances within each condition. Paired differences use jointly timed repetitions of the same instance. Bootstrap draws use the same seeded instance samples as other measures; draws with no timing have unavailable timing. Saved analysis includes run/instance denominators, per-instance timed-repetition counts and usable bootstrap counts. The timing estimate describes the available subset under shared load; all accuracy and observed-token repetitions remain included.

Attempts without a returned response may have generated tokens whose usage cannot be recovered from this ledger. Report their counts and describe token totals as server-returned usage from observed responses. Do not claim that these totals measure all computation performed by the server during interrupted attempts.

Affected source manuscript paragraphs: P150 (request recovery and evidence), P151 (time per run), P152 (instance averaging and intervals), P157 (Table 7 timing note), and P163 (timing limitations). Simon's approval closes this timing proposal. Empirical collection and the results-bearing manuscript remain pending.

## Closed review decision: scoring, diagnostic validation and parser edge case

Codex reviewed Claude commits `8c6dbb3` through `6be6199` on 7 October, after implementing Simon's thread-safety and timing instructions. Simon approved the repairs on 8 October, as recorded in the table above. Claude implemented them in `7e7083a`. Codex reviewed that commit and independently reran the software tests and original held-out-fixture probes. These are software checks, not model performance results. Commit hashes in this file refer to the private development repository; `EXPORT-MANIFEST.json` records which of its commits this copy was exported from.

Before repair, on `heldout-004`, LOC accepted `Radius 284.08 NM; speed 7.06 knots` for the reference `7.06 NM circular orbit, 284.08 kts`. CFG accepted `aircraft 2 to SHELL 20` for `aircraft 2 to SHELL 2`. The repaired checks require exactly one radius in NM and one speed in kts or knots within the existing 0.01 tolerance, and the required tanker name in full in the line from aircraft 2. The original incorrect examples are now rejected while the tested paraphrases remain accepted.

Before repair, the built runtime's hand-offs had enum constraints, but `task_models()` used by diagnostics, calibration and independent analysis did not. An ACK with `instruction: invented_enum` was runtime-invalid yet diagnostic `handoff_valid` was true. Constraints now belong to `task_models()` and are used by every validation path. The invalid-enum diagnostic is rejected, and the exported schema was regenerated in `b1d17d6` with a consistency regression. Recalibrate in the new frozen directory rather than rewriting old evidence.

The approved parser repair tries opening braces in order and selects the first complete object containing `decided`, falling back to the first complete object for the task-keyed single-model response. The leading-prose brace example now parses as approved. Schema/confidence validation and rejection of non-finite JSON constants remain in place. A nested payload without `decided` is not promoted to a valid per-task answer when its outer reply is malformed.

Affected manuscript paragraphs: P147 (parsing/malformed replies), P151 (content scoring and enum validation), P152 (diagnostic validity/calibration), and associated saved protocol/specification files. This review decision is closed. The independently confirmed cluster/bf16 pivot is recorded separately by Claude; medium effort, output cap, repetitions, held-out split, numerical tolerances and approved timing remain unchanged. Frozen collection now awaits the cluster preparation and held-out verification, not another decision on these review repairs.
